# ADR 0004: v0.1 public API and compatibility policy

- Status: Accepted
- Date: 2026-08-19

## Context

A parser library can accidentally freeze low-level implementation details into its public API. pgdumpx also needs a clear policy for byte/text handling, resource limits, errors, and supported PostgreSQL archive versions before code is written.

## Decision

### Source ownership

The core public archive type owns a caller-provided `Read + Seek` source.

### Byte-first strings and rows

Archive strings and COPY fields remain accessible as bytes. UTF-8 conversion is explicit and fallible.

### Data-location fidelity

The public model preserves the distinction between:

- no data;
- data position not set/unknown;
- a valid stored offset.

### Lazy payload API

Raw selected-entry data is exposed through a streaming `Read` implementation that yields decompressed bytes.

COPY rows are exposed through a separate row reader layered on top of the entry reader.

### Row borrowing

The high-performance row API may return rows/fields borrowing from an internal reusable row buffer. Consumers needing ownership can copy explicitly or use a future convenience API.

### Errors

The public `PgDumpError` is typed and `#[non_exhaustive]` before v1.0. Callers do not need to parse human-readable strings to classify failures.

### Resource limits

Finite configurable limits are part of the initial public API for TOC count, string bytes, dependency count, row bytes, and field count.

### Compatibility

v0.1 supports archive versions 1.14–1.16 only. Unsupported versions fail explicitly.

### Serialization

Serde is optional if added. CLI JSON presentation must not accidentally freeze every parser-internal field as a stable wire format.

### Licensing

The project uses `MIT OR Apache-2.0`.

## Consequences

- bindings can build on a stable conceptual stream rather than owned giant buffers;
- callers can safely handle non-UTF-8 database data;
- resource policy is visible rather than hidden;
- pre-1.0 evolution remains possible;
- older archives require explicit later compatibility work.
